# AI利用量レポートの生成と配信

## 生成物

`report/usage_charts.py` が次を生成する。計算はスクリプトが行うので、
エージェントが数値を再計算してはいけない。

- `usage_tables.md`: 日次テーブル（ベンダ別・モデル別。行はその日の
  実測に現れたモデルだけ）
- `usage.html`: 日次推移の積み上げ面グラフ（範囲内の累積。最も
  古い日から日次実測を累積し、右端が期間の合計になる。帯は下から
  Claude、Codex の順に積み上げる。帯の色は大きな面同士の色差を
  抑えるため、棒・円の階調パレットとは別に、明度を落とした深い
  色調のペア（Claude #c24b42 / Codex #3f66b3）を単色で使う。
  上端がそのまま
  合計なので合計の線は重ねない。凡例は帯の中に色チップ・製品名・
  累積の最終値を書き、帯が薄い場合はグラフの右側に書く。
  横軸は日付、縦軸は上部の利用量／金額トグルに連動し、
  期間は週次／月次タブで切り替わる。ベンダ別系列は日ごとのモデル別
  実測をベンダ別に合算して作る）、モデル別グラフ（タイトルは「モデル別利用量／モデル別
  金額」。ベンダの区切りを置かず全モデルを同列に並べ、表示順は
  Claude → Codex、グループ内は指標の降順。棒の中にモデル名、数値
  は棒の外。名前が棒に収まらない行は名前も棒の外）、利用割合の
  円グラフ。いずれも利用量／金額の2バリアントを切り替える

## 前提

- ai-usage-aggregator が稼働し、API キーで `/v1/report` を
  取得できること
- Python 3.11 以上。依存は標準ライブラリのみ（追加インストール不要）

## 導入

このリポジトリを clone するだけ。スクリプトは `report/usage_charts.py`。

## データ取得

スクリプトが次の優先順で取得する。エージェントは自分の環境に合う
ものを用意すればよい。

1. 取得済み JSON を渡す: `--daily-json` / `--weekly-json` /
   `--monthly-json`（いずれも /v1/report?group_by=model の応答。
   期間はスクリプトが決める対象日に合わせること）。折れ線グラフ用
   の日次系列は `--weekly-days-json` / `--monthly-days-json`
   （/v1/report?group_by=day の応答）で渡す。渡さない場合は API /
   ヘルパーから group_by=day で取得する。折れ線のベンダ別系列は
   API / ヘルパー経由で取得した場合のみ描き、日次系列を JSON で
   渡した場合はトータルのみになる
2. 環境変数で直接取得: `AGGREGATOR_BASE_URL`（既定
   `http://localhost:8000`）と `AGGREGATOR_API_KEY`
3. Muse のカスタムコネクタ（custom.ai-usage-aggregator）がある環境
   では、そのヘルパーを自動で使う

## 実行

```bash
python3 report/usage_charts.py [--out DIR] [--date YYYY-MM-DD]
```

- `--date`: 日次テーブルの対象日の上書き。省略時は JST 12:00 前は
  前日、12:00 以降は当日
- 週次・月次は常に前日を末日とする（週次は7日間、月次は30日間）。
  `--date` を指定しても起点は変わらない
- `--out`: 出力先。省略時は `report/reports/`
- テーブルは標準出力にも出る

## 配信フォーマット

レポートは次の形で届ける。推定値や料金プランとの比較は付けない。

1. 1行目: **AI使用量レポート（YYYY-MM-DD）**（日付は生成日）
2. 2行目: 金額は API 換算の参考値。
3. `usage_tables.md` の内容をそのまま載せる
4. `usage.html` を添付する

対象日に実測が無い場合は、テーブルが空になる。その旨を 1 行で伝える。

## 定期実行

毎日朝（利用者のタイムゾーンで 07:00 目安）に上記の生成と配信を
スケジュールする。失敗時は再試行 1 回まで。それでも失敗したら、
失敗した手順とエラー内容を短く報告する。
